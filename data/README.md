# data/ — the data contract + layout

Governed by the **two data contracts** of ADR-0057, instantiated for DispatchLab's truck-shovel dispatch domain.

## Layout

| Path | What | Git |
|---|---|---|
| `examples/scenarios.csv` | a tiny sample of dispatch scenarios that PASS Contract 1 (clone-verify) | committed |
| `derived/dl-policy.onnx`, `derived/dl-bcbest.onnx` | the two learned dispatch policies, exported for live inference | committed (small) |
| `derived/dl-learned.json` | the learned-policy metrics (imitation accuracy, weights, best policy) | committed |
| `derived/case-results.json` | the 8 cases' multi-policy DES comparison (baked by the SAME TS DES the browser runs) | committed |
| `derived/<case>/trace.json` | the compact per-case replay artifact (Contract 2) | committed (regenerated by the pipeline) |
| `derived/manifests/` | per-case `<case>.json` (Contract 2) + the flat `index.json` | committed |

The committed `derived/` artifacts ARE the offline lane's real outputs — the DEFAULT pipeline (`python -m
dlab.pipeline all`, numpy-only) rebuilds the per-case traces + manifests from `case-results.json` + `dl-learned.json`,
so a clone replays without torch or Node. `pipeline all --retrain` regenerates everything (Node DES dataset → torch
train → ONNX; re-bake case-results).

## CONTRACT 1 — ingestion (dispatch scenario → pipeline) — the *bring-your-own-mine* gate

Defined in `data-pipeline/dlab/io/contract.py`. A scenario row is **accepted** iff it satisfies the schema;
ill-formed scenarios are **rejected** with a reason; severely over/under-trucked fleets (match factor far from 1) are
**flagged**.

| Column | Unit | Rule |
|---|---|---|
| `case_id` | — | non-empty |
| `n_shovels` | — | [1, 40] |
| `n_trucks` | — | [1, 400] |
| `truck_model` | — | ∈ {793F, 789D, 777G}; else **reject** |
| `shift_sec` | s | [600, 86400] |

Match factor `~ n_trucks / (n_shovels · 4)` outside [0.4, 2.5] → **flag** (dispatch barely matters / queues dominate).

## CONTRACT 2 — artifact (pipeline → web)

Each run writes a compact per-case trace (`derived/<case>/trace.json`, schema `dispatchlab.trace/v1`) + a manifest
(`derived/manifests/<case>.json`, schema `dispatchlab.manifest/v2`) recording the category, seed, engine+version, the
shared ONNX, the trace byte size, the lane/gate verdict, the Contract-1 flags, and the case metrics.
`frontend/src/lib/contract.types.ts` mirrors these; `scripts/check_artifacts.py` (CI) enforces byte-consistency.

## Provenance / honesty

The DES is a **deterministic discrete-event simulation**, NOT a real plant. The two learned policies are
**competitive** (within ~1% of the best heuristic that taught them), NOT a fabricated RL win. No real fleet-management
data is used or claimed.
